# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Bun + Turborepo monorepo: `apps/web` (TanStack Start on Cloudflare Workers + D1), `packages/db` (`@repo/db`), `packages/services` (`@repo/services`). Run everything from the repo root.

## Commands

- `bun run dev`: applies local D1 migrations and `packages/db/seed.sql`, then serves :3000. No Cloudflare account or env vars needed.
- `bun test`: whole repo. One file: `bun test packages/services/src/bookings.test.ts`; add `-t "name"` for one test.
- `bun run check`: lint (Ultracite/Biome) plus `tsc` in every package. `bun run fix` formats. The pre-commit hook runs `ultracite fix` on staged files, so a commit can fail on unfixable lint.

## Rules

**Request flow is route → tRPC router → service → db query function.** Put validation and permission rules in the service, never in the router or `@repo/db`.
- Why: services re-parse their own zod input so non-tRPC callers (scripts, tests) are covered; db functions are deliberately unvalidated. Routers stay one service call.

**Services take a drizzle `Database` and never read `env`, bindings or the request.**
- Why: the same code runs on D1 in the Worker and on `bun:sqlite` in tests. The D1 binding is read in exactly one place, `apps/web/src/server/trpc/context.ts`.

**A new service needs a line in `context.ts`; a new db or services module needs its own `src/<name>.ts` and its own `exports` entry in that package's `package.json`.**
- Why: there are no barrel files, so an unregistered module simply fails to resolve.

**Browser code may import only `@repo/db/shared`.**
- Why: every other `@repo/db` entry imports drizzle and would bloat or break the client bundle. UI-needed types and limits go in `shared.ts`.

**Throw `ServiceError` subclasses (`NotFoundError`, `ValidationError`, `ConflictError`, `ForbiddenError`) from services, never `TRPCError`.**
- Why: `init.ts` maps them to 404/400/409/403. Anything else surfaces as a 500 with its message hidden in production.

**Mutations take the acting member's id first (`actorId`) and call `requireMember` / `requireAdmin`.**
- Why: there is no auth. `ctx.userId` is always null, so `protectedProcedure` always returns 401; don't use it for team features.

**Schema changes: edit `packages/db/src/schema.ts`, run `bun run generate` in `packages/db`, commit all of `migrations/` including `meta/`.**
- Why: drizzle diffs against `meta/` snapshots; without them the next generate recreates existing tables. Wrangler applies migrations, drizzle-kit does not. Run `db:apply` after.

**Tests use `createTestDatabase()` from `@repo/db/testing`; services tests use `src/fixtures.ts`.**
- Why: it applies the real migrations to in-memory SQLite, so tests cover schema and queries too. It imports `bun:sqlite`, so it must never be imported by app code.

**Don't hand-edit `apps/web/src/routeTree.gen.ts`.** It is generated by TanStack Router.

**`apps/web/src/components/ui/` is shadcn output.** Compose it; don't restyle it in place.

## Templates

Copy `notes.ts` (db and services) for a new table/service; `bookings.ts` shows richer rules (availability, daily limit, rescheduling).
